# HBR 战斗数值测试

此分支将现有角色、本体、幻影和浮游炮接入一套属性驱动的战斗数值层，并采用 HBR 的数值量级。卡牌、OD、掷骰和六感出牌效果继续保留。这里的“六维战斗属性”指力、器用、知性、体力、精神、运；已确认六感等级会提升对应的战斗属性。

这是战斗数值层的测试适配，**不代表已经完整复刻 HBR 原作所有角色和敌人的数据**。下列内容区分社区已实现的公式、尖塔适配参数与尚未核实的行为。

## 存档和成长

- 测试版本新开的一局初始化战斗等级 1，六维基础各为 100，再叠加开局已分配六感提供的加成。
- 普通、精英和 Boss 战胜利分别提升 1、2、3 个战斗等级；每级六维各增加 4。胜利记录去重，读取同一存档不会重复发放。
- 浮游炮继承本体六维。幻影在本体六维上保留其独立等级加成，每超出 1 级各加 2 点。
- 六感点数与分配规则保留；在已启用 HBR 数值的新局中，六感等级的直接收益由对应牌出目每级 +1 改为对应战斗属性每级 +2。领袖魅力、温柔等原有的出牌加骰效果继续保留。战斗成长记录与六感记录分别保存。
- 没有启用标记的旧存档继续使用旧数值；读取旧档、打开手册或复制遗物不会擅自迁移这局的 HP、DP 和属性。
- 已启用 HBR 模式的测试存档按当前平衡参数派生六维，因此此次基础值从 200 调为 100 也会影响这些测试存档；战斗等级、六感分配与胜利记录保留，已有 HP/DP 不重新缩放。
- 多人新局只要包含本模组角色，全队使用同一数值层。原版队友复用原有多人手册保存属性，并且只在新局初始化时转换一次 HP；完全由原版角色组成的队伍不启用。
- 手册“战斗属性”页显示启用状态、战斗等级、六维和当前战斗敌方状态值。旧档显示未启用说明。

### 六感与战斗属性

| 六感 | 每级对应战斗属性 |
|---|---|
| 疯狂 | 力 +2 |
| 领袖魅力 | 器用 +2 |
| 才能 | 知性 +2 |
| 温柔 | 体力 +2 |
| 精神力 | 精神 +2 |
| 单纯 | 运 +2 |

每项战斗属性的数值为 `100 + 4 ×（战斗等级 − 1）+ 2 × 对应六感的有效等级`。有效等级从**已确认的六感等级**计算，继续保留全能之人、萝莉形态等现有有效倍率。未确认点数不计入六维；手册六感页可以预览确认后的收益，切到战斗属性页仍显示当前已生效的数值。

六感等级本身不再给卡牌掷骰增加固定点数；六感出牌效果、抗性削减、兼具阈值和奖励规则继续保留。例如领袖魅力打出后给下一张非攻击牌的出目加值、温柔打出后提供的本场出目加值仍然有效。旧档未启用 HBR 模式时，继续使用原来的每级出目 +1，并显示原说明。

卡牌悬浮提示、手册描述和词条全解按本局模式选取独立的 `hbrDescription`，不覆盖旧档使用的本地化条目。战斗属性页同时显示对应六感、已确认等级、有效等级与属性加成；刷新缓存包含六感原始及有效等级，确认分配或形态倍率变化后更新现有控件，不逐帧重建界面。

### 生命与固定资源效果

这里的“100 倍”以原始尖塔数值为基准：初始生命从之前的 ×50 调整为 ×100，不是再把当前已放大的生命乘 100。按用户确认，DP 继续保持与 HP 的比例，因此初始 DP 同步增长；不将 DP 与生命上限拆开。

固定数值效果在明确来源处换算，例如回复 6 HP → 600 HP、失去 5 DP → 500 DP、获得 10 DP 上限 → 1000 DP 上限。`HbrResourceValueHelper` 为这些原始量提供一次换算入口；原有最终 HP/DP 写入 API 继续接收实际资源量。卡牌变量、升级与存档仍保存原单位，描述与实际消费同时使用换算结果。

难以杀灭的原生单次上限9在HBR模式中为900；硬化外壳的原生每回合上限20为2000（多人等机制若先将原值改为40，则为4000）。这两项采用固定HP数值×100，与怪物最大生命值的700倍校准独立。上限、剩余量徽标和提示共用同一读取入口，本回合已受到的实际伤害不再放大；原生层数、复制和存档仍保留原值。幻影融合按最大HP百分比生成的上限已是实际HP单位，无论数值大小都不再换算，超过原生数值范围时继续使用精确上限。无实体的1点上限与持续回合数保持原规则。

[限伤验证](../validation/hbr-damage-caps/README.md) 调用真实原生能力和累计账本，覆盖限值、显示、累计扣除、回合重置、多人原值、复制和两种大小的幻影生命比例上限；不替代游戏内测试。

原版固定效果按 `HbrNativeFixedResourceHelper` 的模型／变量清单，在消费和文本读取处换算；不修改 `DynamicVar` 原始 getter、升级、克隆或存储值。打击等普通攻击技能仍走技能伤害路线；燃烧等明确的状态牌自损、固定回复遗物、生命上限奖励和固定事件代价单独适配。蜥蜴尾巴、血药等百分比数值与已经算好的事件回复不在固定值清单内。原生层数型回复、固定最大生命损失及知识恶魔的定额回复在各自命令消费处转换。不会按输入数字大小猜测第三方效果的单位。

浴池的下一次伤害原值仍按 `3 → 4 → 5` 累加，只在实际消费时得到 `300 → 400`；不能将 300 写回原始变量。幻影每级最大 HP +5 同样在资源应用时得到 +500，融合与继承元数据仍保存原值，临时等级只记录已应用的实际加值，移除时扣除该记录，不再次乘 100。

卸下庇护在战斗开始时自动打出并消耗，清除当前DP，将其一半向下取整后转为本场临时最大HP，同时恢复实际增加上限的等量HP；伤害增幅按清除DP的5‰计入百分比。例如1000 DP换取500临时最大HP、恢复500 HP及5%伤害增幅，升级仍额外抽2张牌。它消费的DP和增长后的实际HP不再套固定值×100。转移至幻影时沿用既有等量恢复路径，不给本体或幻影重复恢复；战后撤销临时上限并按原账本返还DP。

[卸下庇护验证](../validation/beyond-protection/README.md) 执行实际卡牌、伤害增幅银行和DP账本，检查消耗、升级、奇数DP、生命封顶、31O幻影转移和战后一次返还。Heal命令的表现与末端Hook被隔离，实际生命写入使用原生方法；未启动游戏或验证自动出牌后的原生牌堆移动。

百分比恢复/损失按当前资源计算，满血/重生/转阶段设值沿原规则，实际伤害返还、吸收、溢出转换、退款和跨战斗保存量不通过固定值入口。我方攻击技能走现有技能倍率与单一线性属性系数，不再把结算伤害乘 100。

新局、混合队伍的新原版角色以及新生成幻影使用新的初始生命倍率。已有存档中的 HP/DP、幻影名单与永久增减记录不会在读档、克隆或打开手册时整笔重缩放；已有 HBR 局后续触发的固定效果使用新的 100 倍规则。未启用 HBR 的旧模式保留原值。

### 力量与敏捷

HBR模式中，力量和敏捷是实时属性来源：我方每层力量使力、器用各增加1，每层敏捷使知性增加1。它们不再在伤害／格挡的原生加算阶段额外加值；负层数按相同幅度降低属性，有效属性最低为0。属性按读取时派生，状态移除后自动恢复，不改写手册基础值、六感分配或存档中的力量／敏捷层数，临时力量／敏捷的到期计数也不重复参与一次。

怪物力量在攻击计算时，从目标的体力与精神各忽略 `力量层数×本幕系数`；怪物敏捷在受击计算时，从攻击者的力与器用各忽略 `敏捷层数×本幕系数`。第一至第五幕系数依次为1、2、3、4、8，第六幕及以后保持8。各维先单独截断到最低0，再按技能的权重计算，不改变角色面板或下一次攻击的属性。负层数按相反方向调整。怪物敏捷不再额外提供原生固定格挡。

浮游炮的伤害与格挡使用本体当前力量／敏捷一次；幸福Lv.3保留正力量收益翻倍，对该炮的攻击额外增加一份力与器用。幻影继承本体的基础成长与六感属性，叠加自身等级及自身力量／敏捷，不把本体临时状态再继承一次。思念Lv.2经“还会再见的”提供的额外敏捷一并计入本体知性，不再从另一条路径增加原始格挡。明确依赖敏捷层数的卡牌段数、融合技能加伤等额外效果仍保留。

例如固定状态值150、六维100且不计骰子／暴击／其他增减益：打击原始威力3857.14，获得1层力量后为3900；面对第一幕1层敏捷的敌人时为3814.28。防御原500格挡，1层敏捷后为505。资源派生攻击、已结算追加伤害与HP专属反应保持原有单位边界；旧模式继续使用原生力量加伤、敏捷加格挡。

伤害与格挡的最终结算值向下取整。伤害属性与乘区按原有精度计算，在完成全部增减益、浮游炮灵魂之力和限伤后，统一输出非负整数，供预览、HP／DP扣除与伤害记录使用；例如上面的3857.14和3814.28分别结算为3857和3814。不会在每个乘区之间反复取整，也不会四舍五入。

[力量／敏捷验证](../validation/hbr-stat-powers/README.md) 执行真实属性读取、原生力量／敏捷与伤害／格挡Hook，检查临时状态、炮与幻影来源、逐幕忽略量、描述和最终取整；其中预览与实际伤害包装器使用同一共享管线。不启动游戏或替代实机界面验收。

### 脆弱

HBR模式中，脆弱的修改器强度与持续时间分开。每次施加使用单一基础效果，保留原作减益的知性、运权重和正属性差成长斜率，不使用最低／最高威力端点或阈值转折：

```text
参照属性 A =（施加者知性 + 2 × 施加者运）÷ 3
基础脆弱百分比 B(n) = 30 × 1.25^(原始修改器层数n − 1)，n≤0时为0
本份脆弱百分比 = B(n) × [1 + max(0, A − 状态值E) × 0.001]
```

未选目标时，卡面显示基础脆弱百分比，选定目标时显示该次属性计算后的实际值。显示保留一位小数，结算保存完整精度：迅雷风烈原始修改器2对应37.5%；冰华千射万箭原始3对应46.875%（显示46.9%），达到弓牌阈值时将两次原始3合并为一次原始6，对应91.552734375%（显示91.6%），不是两份46.875%相加。原始变量、升级与克隆仍保存修改器单位。

脆弱不再堆叠持续回合，而是最多并存两份独立能力，效果相加。每份初始持续2回合，原生Amount仅表示剩余回合；回合结束时各减少1，强度不随回合减少。满额时先选择强度最低的一份，同强度选剩余时间最短的一份；新效果不低于该份时替换，持续时间重置为2，否则丢弃。不同来源独立保存已结算百分比，命中与预览直接读取，不重复解析存档或读取施加者属性。旧档缺少快照时暂按原施加者与旧修改器读取，下次生命周期衰减前一次迁移为不超过2回合。

浮游炮沿本体属性，幻影沿自身等级与属性；敌人或无法追溯来源时使用B(n)，不为敌人虚构六维属性。未另行迁移的旧脆弱强度收益仍读取各份保存的原始修改器之和，避免误用剩余回合。「翻倍」将每份现有脆弱已结算的效果数值与剩余回合数各乘2，不新增实例，不重新计算施加者属性，也不改变原始修改器强度；例如37.5%、剩余1回合变为75%、剩余2回合。「弱点打击」只将目标每份现有脆弱的效果数值乘2，持续时间不变。「将痛楚重奏」将打出前已有的每份脆弱按原快照复制一份，新副本持续2回合，复制份数不设上限；同一次出牌不会再复制刚生成的副本。其它正向修改仍服从普通两份上限与替换规则；剥离脆弱会移除全部实例，同一能力种类只支付一次奖励。旧模式维持固定150%及原有叠层行为。

「穿透射击」读取每个目标独立脆弱的实际效果总和，包含伤痕的最终增强，每1个百分点使技能系数增加0.006（6‰）；升级后为0.012（12‰）。「刚射」采用敌方可命中目标中的最高总百分比，对每段攻击应用同一系数加值，升级同样保留原先加成翻倍。以打击100%对应原始6点为基准，额外原始单位为`脆弱百分比数值×0.036`（升级×0.072），再统一进入属性与后续伤害路线；不是将当前卡牌威力再乘以该比例，也不读取持续回合或原始修改器层数。

「模仿-全身铳击」给予脆弱后，只检查实际目标是否处于Break。每满10个百分点脆弱（升级后5个百分点），额外增加1个百分点破坏率，不足一档的部分不提供额外层数。然后以实际脆弱百分比数值×100作为基础伤害，交由共享伤害管线应用更新后的破坏率一次：50%脆弱和150%破坏率对应7500点，再参与正常属性、掷骰、减益等加成。不会把破坏率预先乘入基础值后再重复计算。

脆弱继续只在目标处于Break时生效，进入共享减防加算区，最终伤害统一向下取整。「伤痕不会自行消失」升级后，对攻击力下降、防御力下降、脆弱的最终异常效果乘以`1＋累计增强百分比÷100`，不再额外加百分点；例如30%的异常效果在25%增强下变为37.5%。脆弱先按属性计算并保存快照，再在读取时增强一次；多次升级副本的增强百分比沿原规则累加，自然衰减拦截不变。统一施加入口保留原生施加／接收修正、人工制品阻挡、历史与回调，不因改为独立实例绕过减益阻挡。

### 攻击力下降与防御力下降

攻击力下降与防御力下降是独立HBR能力，分别使用`HbrAttackDownPower`与`HbrDefenseDownPower`。原版虚弱、易伤保留原类型、图标、说明、固定比例、叠层／持续时间及纸鹤、纸蛙、残废、残酷等原版联动。原版卡牌、药水、遗物和敌人继续施加原版能力；模组自己的卡牌、幻影、浮游炮和怪物通过显式适配器，在HBR模式下施加新能力，旧模式仍使用原能力。不在全局原生施加入口根据持有者猜测或替换类型。

两种新能力的基础效果为`15%×1.25^(原始修改器层数−1)`：1层15%、2层18.75%、3层23.4375%。属性参考值为`A＝(2×知性＋运)÷3`，施加时保存`基础效果×[1＋max(0，A−目标状态值E)×0.001]`，不使用最低／最高端点。无六维属性的施加者使用基础效果。卡面显示基础百分比，选择目标后显示实际效果，保留完整结算精度。脆弱保留自身30%的基础与知性／运权重。

每种通常最多并存两份独立实例，每份初始2回合，每次持有者正常回合结束减1；满额替换、同强度优先替换较短持续时间、人工制品与免疫阻挡均共用脆弱流程。「将痛楚重奏」按出牌前快照复制这两类异常时不受份数上限限制，各新副本仍持续2回合；已有超额副本时，普通施加仅按原规则替换一份。两份15%攻击力下降按剩余伤害分别乘算，得到`0.85×0.85＝0.7225`；两份15%防御力下降进入共享减防加算区，得到`1＋0.15＋0.15＝1.3`，不要求Break。原版弱易使用独立原生乘区，可与新能力同时存在；例如原版易伤1.5倍再乘新防降1.3倍，得到1.95倍。

「伤痕不会自行消失」的HBR增强与衰减保护只作用于新攻击力下降、新防御力下降及脆弱。原版遗物的Weak／Vulnerable修正不会套用到新能力。「翻倍」对每份新能力的现有效果与剩余回合各乘2；清除一个异常种类时移除其全部实例。强度与百分比是新能力自身声明的保存字段，原生保存／网络往返及克隆沿模型原有机制处理，不再向原版能力追加百分比元数据。

「海风高压电」只将新防御力下降的基础效果乘2，再按知性／运与目标状态值计算并保存快照。例如基础15%、属性系数1.1时保存33%；不会额外获得纸蛙对原版易伤的加值。已有快照、复制与「翻倍」不重新计算海风；胜负Lv.6从脆弱快照生成独立防降视图时应用同一增幅，原脆弱不变，原版易伤查询不会读到该视图。

两种新图标使用本地提取的HBR原作`IconBuffAttack`与`IconBuffDefense`纹理，来源、原作状态对应及哈希分别保存在`images/powers/hbr_attack_down_power.sources.json`和`hbr_defense_down_power.sources.json`。原作的下降标签由运行时另绘，本次未自行拼接箭头或标签。

手冢咲的「鬼神状态／重点突破」在HBR模式下采用普通「刚射」的6‰系数收益：当前目标每有1个百分点防御力下降，本次技能系数增加0.6个百分点；50%防御力下降对应增加30个百分点。按各活跃实例保存的百分比求和，并计入伤痕最终增强一次，不读取剩余回合或原始修改器强度。无真实防御力下降时可沿胜负Lv.6的虚拟视图判定；其它目标的异常不参与。本次原始伤害单位先增加`防御力下降百分比数值×0.036`，再进入现有敌方或幻影的属性换算，不在换算后的伤害上再加旧的每层2点。重点突破的单段攻击与交替减益不变，其它招式不获得这份加成。

[能力验证](../validation/hbr-fragile/README.md) 与[卡面验证](../validation/hbr-fragile-cards/README.md) 覆盖公式、来源、独立持续／替换、序列化、说明和共享伤害管线；不替代游戏内验证。

所有敌方状态值按地图位置适配：

```text
状态值 = 150 + 60 × 幕索引 + 6 ×（本幕层数 − 1）+ 房间修正
幕索引从 0 开始，本幕层数最低为 1；Boss 修正 +50；精英修正 +30；普通 +0。
```

第一幕第 1 层普通怪（含 SmallHopper）的 `E = 150`；之后 SmallHopper 与其他怪物一样随位置成长。每层 +6，进入下一幕额外 +60，精英再 +30、Boss 再 +50。成长直接按当前地图位置计算，不累计写入存档，不因召唤、重入或阶段切换重复增加，也不根据玩家等级或六感变化追赶。

| 位置 | 普通 | 精英 | Boss |
|---|---:|---:|---:|
| 第一幕第 1 层 | 150 | 180 | 200 |
| 第一幕第 10 层 | 204 | 234 | 254 |
| 第一幕第 17 层 | 246 | 276 | 296 |
| 第二幕第 1 层 | 210 | 240 | 260 |
| 第三幕第 1 层 | 270 | 300 | 320 |

这些默认权重是兼容既有牌池的映射策略，不意味着 HBR 原作对每张技能都按当前 DP/HP 状态切换权重。原作技能可以指定自己的属性引用；后续应逐项建立技能配置。

### 敌方能力、资源与技能

HBR 的敌方数据使用独立状态值 `E`、最大 HP、最大 DP；它们不是把玩家的六种属性复制给敌人，再按体力和精神推导资源。参考数据中，DeathSlug 两形态的状态值都为 290，HP、DP 却分别配置为不同数值。[冻结敌人数据](https://github.com/hbr-tool/damage-calculator/blob/ead9f319d18fb47e749718adac0d4384b785c0bc/src/data/enemyList.js#L2-L15)

`HbrEnemyProfileHelper` 负责敌方状态值，玩家、幻影和浮游炮继续使用 `HbrBattleStats`。敌人不再返回六个相同的伪属性。SmallHopper 的第一层基准为 150，之后所有敌人按同一地图公式成长；不会仅凭 Boss 名称，将另一种遭遇、异时层或阶段的数据直接套入。

`HbrEnemyResourceProfile` 分别声明原生参考 HP、对应最大 HP、对应最大 DP。用户将 Hopper 的参考 HP 比例取整为 700 倍，并指定柴犬单独为 1000 倍。因此默认兼容配置为 `(1, 700, 200)`，SmallHopper 为 `(14, 9800, 3000)`，柴犬为 `(1, 1000, 200)`。默认 DP 参考仍为每点原生 HP 对应 200 DP，SmallHopper 保留单独校准的 3000 DP；HP 先取整，再按现有规则计算新生成的 DP。DP 参考值按默认 20% 壳配置标定，实际 DP 百分比、成长和难度仍由现有壳计算器处理。保留原生随机 HP、难度、多人和阶段顺序；原生多人血量先按原规则取整，再进行资源适配。**为兼容尖塔，后续最大 HP 变化仍会同比影响重新生成的 DP，并未完成原作逐怪固定 HP/DP 表迁移**。普通壳、手塚的全资源壳与柴犬的初始多层 DP 走相同的资源入口。已有 DP 和存档数值不再次换算；柴犬的层上限继续在初始化时冻结。

例如默认配置下，非柴犬敌人的原生 HP 为 28、70、140 时，分别对应 HP 19600、49000、98000。该规则适用于普通、精英、Boss 与新召唤的敌人，也适用于已有阶段替换入口；每个新实体仅转换一次，盟友、宠物和幻影排除。未启用 HBR 的旧模式保持原规则。此改动不批量迁移存档已有的实际 HP/DP，也不逐帧扫描怪物。

`HbrEnemySkillProfile` 分别配置威力下端、上端、参数阈值和防御参考。当前基础端点仍为旧技能每段伤害 ×100/×200，阈值 140，是尖塔适配值；原作者说明阈值可随敌遭遇或变体而不同。没有原作对应数据的技能采用固定体偏配置；RedCrimsonBoss 的消失光线及两条超新星技能显式采用精偏，也是本模组的适配分工。其他原版与外部模组技能尚未逐条配置，不能宣称已经取得它们的原作数据。

令 `D` 为该技能选用的防御加权值、`d = E − D`、`L/U/T` 分别为威力下端、上端和参数阈值。受击基础威力使用独立函数：

```text
d ≤ −T      P = 1
−T < d < 0  P = max(1, L × (1 + d/T))
0 ≤ d < T   P = L + (U − L) × d/T
d ≥ T       P = U
```

该基础曲线参照[カンタータ仮面的公式整理②](https://note.com/gazou774/n/n82b99b359f2b)（2025-08-03图版）；防御权重参照同文④（2026-04-29图版）。这是社区研究，非官方精确式。作者用“主要单体／主要全体”描述两类参考，不能据实际目标人数反推技能类别。后续增减伤、格挡、DP 与最终取整仍由现有管线处理；这次没有新增 ±10% 随机浮动，也没有给敌人套用玩家的运与天然暴击。

敌方受击曲线在上端封顶；我方出伤使用独立的单倍率线性规则，没有上下端和超阈值分支。敌方格挡继续使用原有 E 支持曲线，不套用我方知性规则。意图预览和实际伤害读取同一份技能配置，不再为推断防御类型提前枚举目标。反伤、荆棘、生命比例和已结算伤害仍保留实际单位边界，不因来源是敌人就重新当作技能倍率计算。

### SmallHopper 开局基准

本轮目标是普通难度、默认配置下，六维各 100 的角色使用 3～4 张未升级初始攻击牌击杀，使用一张基础防御仍受到少量伤害。用原生铁甲战士的打击、痛击、防御校准；自然暴击、六感附加效果、掷骰和其他增减益不计入这组基准。全原版队伍仍不会自行启用 HBR 模式。

| 参数 | 基准 |
|---|---|
| 状态值 | 第一幕第 1 层普通房间为 150，后续随地图位置成长 |
| 原生参考血量 | 14；普通随机范围 12～16 |
| 最大 HP | 参考值 9800；普通随机范围 8400～11200 |
| 最大 DP | 参考值 3000；普通随机范围 2571～3428 |
| 攻击 | 体偏；威力下端 400、上端 800、阈值 140 |
| 破坏率 | 初始 100%；普通敌系数 2，上限 150% |

打击的基础威力为 3857.14，第一张击破 DP，过量伤害不转入 HP；后续命中随破坏率增长。四张打击可以击杀整个普通随机血量范围。痛击先造成 5142.85 基础威力并击破 DP，再施加易伤；接两张打击可以击杀，共 3 张攻击牌、4 点能量，需要跨回合出牌。

Hopper 对六维 100 的基础受击威力为 542.857…，单倍率防御提供 500 格挡；无玩家 DP 时，原生流程先扣格挡，再由 `LoseHpInternal` 截断剩余生命损失，实际失去 42 HP。普通 DP 在 HBR 模式下不额外提供旧模式的 25% 减伤。700 倍 HP 下，高难度原生 17 HP 对应 11900 HP，在不计其他难度效果的同组测试中也可由四张打击或痛击加两张打击击杀。难度、多人、HP/DP 配置或角色成长会改变实际牌数，不将这组开局基准强制套给所有遭遇。

### 技能倍率配置

普通打击配置为 `100% → 150%`，防御为 `100% → 160%`。多段攻击的倍率始终表示每段倍率，段数、X 费次数、激发和额外行动保持独立。骰子、OD 与伤害增幅在技能威力计算之后沿原分区生效，不回写技能倍率。

我方卡牌、幻影与浮游炮共用 `HbrSkillPower` 的单倍率计算。令伤害技能倍率为 S、格挡技能倍率为 B（以 100% 为 100），A 为对应的 DP／HP 加权属性，E 为当前状态值：

```text
伤害基础威力 = 6000 × S÷100
属性系数 = max(0, 1 + (A−E)÷140)
技能威力 = max(1, 伤害基础威力 × 属性系数)，截断到小数点后 2 位
格挡 = floor(500 × B÷100 × max(0, 知性)÷100)
```

伤害倍率为 0 或负数时结果为 0；正倍率保留 1 点威力下限。140 是属性差的换算单位，不再是技能威力的封顶或分段阈值。例如打击 100% 在 A=E、A=E+140、A=E+280 时，分别得到 6000、12000、18000；防御 100% 在知性 100、200 时分别得到 500、1000。升级后的 150% 伤害和 160% 格挡沿用现有倍率，属性与技能之间不增加第二套上下端数据。

暴击先将 E 改为 `max(0, E−50)` 计算同一个线性属性系数，再沿现有规则乘暴击增幅。自然暴击率、DP／HP 权重、骰子、OD、破坏率和浮游炮灵魂之力的执行顺序保留；灵魂之力仍只在最终伤害应用一次。旧原作出伤曲线保留为研究对照，不再用于我方技能运行入口。

`HbrSkillVars` 为固定伤害、格挡、条件加值、计算型伤害及升级差值提供明确的倍率入口。伤害的三分之一类配置以百分比分子和分母传入，详情页的百分比可以显示两位小数，战斗计算不使用四舍五入后的显示值。浮游炮的基础伤害、格挡、幸福成长及终局公式共用相同基准，伤害末端仍只结算一次灵魂之力。共同增加炮伤害和格挡的卡牌分别显示两种基础增量，详情页附各自的百分比，继续使用原来的同一成长记录。

为兼容原生卡牌升级、附魔、能力、复制和存档，`DamageVar` / `BlockVar` 的键与内部单位仍保持原值；配置入口将技能倍率精确转换为这些兼容单位，统一伤害入口再计算单一基础威力及属性系数。这不是把显示百分数写入原来的伤害字段。未启用 HBR 数值的旧局继续使用原数值和原文案，也不在读取存档时重复转换。

卡牌正文直接显示伤害或格挡数值，只有卡牌详情页在相应数值后附上百分比括号，例如“造成6000点伤害（100%）”，不显示“倍率”二字。战斗中沿用现有伤害/格挡预览；没有战斗目标的百科、永久卡组等页面显示基础威力（打击6000）或按当前知性计算的基础格挡（知性100时防御500），无持有者时以知性100为基准。预览只生成显示参数，不改写卡牌变量、技能配置或存档。单纯与明确的固定技能格挡，也在各自执行边界进行换算；累计实伤返还格挡、终局伤害的 5% 格挡等已计算量不再次换算。

浮游炮采用同一显示顺序：悬停与升级、手册详情先写实际伤害或格挡，再以括号显示技能百分比，例如“获得224点格挡（80%）”，不再写“80%倍率格挡（预计224点）”。战斗中复用炮的现有预览，脱离战斗时使用无目标的自身属性与灵魂之力，不虚构目标状态值；灵魂之力本身仍独立显示为百分比能力。

[卡牌显示验证](../validation/hbr-card-display/README.md) 使用真实卡牌、升级与复制逻辑、原生本地化和 SmartFormat 格式器，覆盖普通/详情文案、嵌套描述、延迟格挡、预览作用域及变量不被显示代码改写。该验证不启动游戏，不替代实际界面验收。

按当前格挡、实际失去 DP 或敌方 DP 上限比例得到的攻击，不是固定技能倍率。这些路径显式跳过技能倍率、属性系数与自然暴击，仍保留附魔、正常增伤和适用的灵魂之力。边界在原生伤害指令和附魔前的 Hook 入口识别原始值，嵌套伤害单独隔离，避免被重复放大。已结算伤害的追加段则继续使用原来的完整预计算保护。

读取幻影当前攻击意图总伤害的卡牌也属于实际数值输入：意图已计算过幻影的技能倍率和属性系数，不能再把它作为原始倍率输入计算一次。该次攻击使用相同的显式边界，旧模式不变。

## 公式来源与范围

采用社区作者项目 [hbr-tool/damage-calculator](https://github.com/hbr-tool/damage-calculator) 的快照 `ead9f319d18fb47e749718adac0d4384b785c0bc`。它对应现行计算器；[old-damage-calculator](https://hbr-tool.github.io/old-damage-calculator/) 已明确停止更新，不能与现行分区混用。

这些是**社区逆向实现**，不是官方发布的精确公式。原作公式本身和本模组数值桥接须分开核对。

### 原作技能威力研究对照与暴击

下列上下端公式作为原作研究参考和冻结向量验证保留；当前我方技能已按用户要求使用上一节的单倍率线性适配。原作研究向量不随本模组平衡改动而重写。

使用归一化加权属性 A、状态值 E、技能阈值 C，以及技能威力下端 L 和上端 U；令 d = A − E：

```text
d < 0       P = max(1, L × (1 + d / C))
0 ≤ d < C   P = L + (U − L) × d / C
d ≥ C       P = U × [1 + (d − C) × 0.0025]
```

威力保留至百分位并向下截断。超过阈值后继续成长，不能硬封顶。技能等级对 L、U 分别使用每级 5%、2% 的增长；额外宝珠分量和具名技能例外尚未移植。[作者实现：技能威力](https://github.com/hbr-tool/damage-calculator/blob/ead9f319d18fb47e749718adac0d4384b785c0bc/src/components/dmgCalc/logic.js#L690-L737)

暴击概率的自然部分为 `min(15%, 1.5% + max(0, 运 − E) × 0.04%)`，暴击率增益另加，总概率最高 100%。暴击先以 `max(0, E − 50)` 重算威力，再乘 `1.5 + 暴伤加成`。降低状态值 50 与其它同类降参取较大降幅，不能直接相加。HBR 暴击与模组骰子大成功分别判定。[作者实现：暴击](https://github.com/hbr-tool/damage-calculator/blob/ead9f319d18fb47e749718adac0d4384b785c0bc/src/components/dmgCalc/logic.js#L890-L921)

### 增减益

当前社区实现把技能/元素攻击提升、心眼、场地等合并进攻击区，把通常/元素/DP 防御下降与脆弱合并进减益区；区内相加，两个区之间相乘。各效果仍需满足元素、弱点、DP 状态等条件。[效果类别表](https://github.com/hbr-tool/damage-calculator/blob/ead9f319d18fb47e749718adac0d4384b785c0bc/src/data/buffEffect.js)

同一个效果类别中，普通效果选最高两层相加；单独发动效果与该两层总和取较大者。各效果类别分别计算，不能把所有攻击提升混成共用两个槽。[作者选择逻辑](https://github.com/hbr-tool/damage-calculator/blob/ead9f319d18fb47e749718adac0d4384b785c0bc/src/components/dmgCalc/logicBuff.js#L76-L132)

纯数值引擎提供叠层选择及属性驱动的增益/减益曲线；现有卡牌能力仍保留各自持续、消耗、永久计数和 OD 规则。它们不因为提供这些数学函数就自动变成原作完整技能状态机。

### DP/HP 与破坏率

社区计算器按段选择 DP/HP 特攻和 DP 防御减益，DP 击破后推进破坏率，后续段使用提高后的倍率；破坏率增量由敌系数、技能系数、提升与抗性决定，与实际伤害量分别计算。普通段平分技能破坏系数，连击追加段按各自比例处理。其默认单层 DP 计算中，击破段的过量伤害不会在同段继续扣 HP。[作者逐段实现](https://github.com/hbr-tool/damage-calculator/blob/ead9f319d18fb47e749718adac0d4384b785c0bc/src/components/dmgCalc/logic.js#L604-L687)
