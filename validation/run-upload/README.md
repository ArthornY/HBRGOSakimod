# run-upload

Offline checks for the run data upload (`Core/RunUpload/Common`). The suite links only the plain .NET half of the feature, so it needs neither Godot nor a game assembly, and it never opens a network connection: every request goes to an in-memory fake transport.

```powershell
dotnet run --project validation/run-upload/Checks.csproj
dotnet run --project validation/run-upload/Checks.csproj -- D:\stsmod\.ai-collab\handoffs\run-upload-20261108
```

The optional argument is the handoff folder. When it exists, the suite checks that `fixtures/schema-v1.md` and `fixtures/example-run-v1.json` are byte-identical to the handoff copies; copy them again after editing the schema.

What it covers:

- **Envelope and serialization**: exactly the seven envelope fields in order, `hbrgo-run/1`, lowercase v4 upload ids, UTC times with `Z`, mod and game version cleaning per `endpoint.md`, restamping `uploadedAt` on retry, UTF-8 Chinese text, a single gzip member, the decompression limit.
- **Example and schema**: the example passes the schema rules; the builder rebuilds the whole example run (map, six floors, two battles turn by turn, choices, HBR snapshots, final state, names) and every example field comes out equal; every field the builder writes is a field named in `schema-v1.md`; enums, creature keys, damage parts, map edges, path and floor numbering are checked.
- **Builder behaviour**: creature keys and card uids, events before the first snapshot, extra turns in one round, per-card `dealt`, result totals, truncation at the event limit, partial records (the format still allows them; the recorder never writes them), resuming a saved record, notes, names, text limits.
- **First-launch prompt**: before the answer nothing is recorded or sent; deny (or closing the prompt) is remembered, stays off and creates no id; allow turns uploading on with an id; an answer or consent from an older `ConsentVersion` asks again and counts as off.
- **New anonymous id**: replaces the id, persists, keeps the switch as it was, does nothing when there is no id yet.
- **Integrity and filter**: known modifier labels (case-insensitive, sorted), this mod and its libraries never count as other gameplay mods; runs with a modifier or the console are dropped, loss or abandon on floors 1–5 is dropped (5 is the user-confirmed constant), another gameplay mod alone is uploaded with its flag; a dropped run leaves nothing on disk; the exclusion marker holds no run data, survives clearing, and is not written while off.
- **Switch off, no request**: a fresh install, a deny, a damaged or outdated consent file and a turned-off switch never create the HTTP client or send a request; turning off mid-pass stops before the next request and cancels the one in flight; queued runs and the install id survive turning off; clearing local data empties the queue and the run in progress.
- **Retry**: 404, 405, 408, 429, 5xx, redirects and network errors keep the run queued with doubling waits (1 minute up to 6 hours) or `Retry-After`; 201 and duplicate 200 deliver; 400, 409, 413, 415, 422 drop the run; the same upload id is reused; oldest first; a failure ends the pass.
- **Queue limits**: at most 50 runs, at most 30 days, 16 MiB uncompressed and 4 MiB compressed, damaged sidecars removed, records stored compressed.
- **Console commands**: the harmless list is exactly the twelve game commands read in the source (`RunUploadConstants.HarmlessConsoleCommands`), compared without case; the 25 networked game commands, `unlock`, `cloud`, `multiplayer`, this mod's `hbrgosakimod`, other mods' and unknown names all count.
- **Which run is recorded** (`RunRecordingGate`, driven by `SessionSim` the way `RunRecorder` drives it; a new `SessionSim` on the same folder is the game started again):
  - console during a run: harmless and failed commands keep the run and it is uploaded with `consoleUsed` false; a run-changing command, `hbrgosakimod` or an unknown name drops the record, leaves a marker, and nothing is uploaded, also after a restart; a modifier mod skips the run;
  - typed console commands still count: a typed line reaches the console patch as its first word (`SessionSim.Typed`, the way `DevConsole` splits it, here or from a teammate), so typing `hbrgosakimod __activate_overclock 2` (any case), the fixed-roll subcommand or `gold 999` excludes the run and nothing is uploaded; a typed OD that failed keeps the run, typed again and opening, it excludes;
  - turned on during a run (also later continued from the save, also off and on again, also local data cleared): that run is not recorded or uploaded, the next new run is, as a whole run (`partial` false, `fromFloor` 1);
  - continued without its record (the switch was off when the run began, another run's record, or the switch off when it was continued): not recorded or uploaded, and the stale record is deleted;
  - continued with its record: uploaded, `sessions` 2, floors continuous, schema rules hold; another gameplay mod in the later session sets its flag; a recorded run abandoned from the main menu is uploaded from its saved record, a skipped one is not;
  - battle interrupted, then continued: the cut-short battle becomes an `interrupted` earlier attempt, the replay is attempt 2, and the run is uploaded.
- **Recorder wiring and texts** (read as text): `RunRecorder` starts a record only when a run starts, never writes a partial header and asks the gate at start, continue, console, end; the console patch passes `cmdName`; the service skips the run in progress when uploading is turned on or off or local data is cleared; the explanation and the settings hover carry the Cloudflare sentence, the console rule and the turned-on-during-a-run rule.
- **OD request** (`Core/Integration/HbrOverclockActivation.cs` is linked; added 2026-11-09 when the user said the party shares OD in co-op, 「谁按都能开」): the payload keeps `Level` and `OwnerNetId` through the round trip (levels 1–3, player ids 1, a Steam-sized id and `ulong.MaxValue`) and holds only those two fields; a null, malformed or negative-id payload is rejected, and one without a player names id 0. `HbrOverclockActivation.Target`, with fake players: the OD holder, a teammate without OD and the second of two holders all open the OD the gauge shows (the first holder's); single player opens their own; a named player who is not in the run, is on the other side or holds no OD, a missing sender and id 0 open nobody's.
- **OD gauge is not the console** (read as text, comments stripped by `CSharpText.Code`; added 2026-11-09 after the user's 「bug修一下」): the gauge asks for OD with `HbrOverclockNetActions.Request(_relic, level)` and builds no console command; the request is a managed action of the local player that names the player whose OD the gauge shows; it is queued as the old `ConsoleCmdGameAction` was (`CombatPlayPhaseOnly` when asked in combat, `Any` outside, one action key each); both keys carry `HbrOverclockActivation`'s own `Serialize` and `Deserialize`; every peer runs `TryActivate` on the player `HbrOverclockActivation.Target` picks, never on the sender's own relic; pressing after ending the turn depends on the local player's ready vote (`Overclock.CanActivateInput`), not the relic owner's; both keys are registered in `HBRGOSakiModInitializer`; none of the mod's 1,100-odd production `.cs` files constructs a `ConsoleCmdGameAction` or calls `ProcessNetCommand`/`ProcessCommand`, so only typed commands reach the console patch; the typed subcommand still exists. The suite cannot run game code, so the gauge itself is checked by reading the sources; the real press is only confirmed in game. Reverse checks are in `D:\stsmod\outputs\od-gauge-console-20261109\reverse.log` (the old gauge put back, the startup registration removed, a console sender added elsewhere or only in a comment, the request made for another owner, `hbrgosakimod` added to the harmless list) and `D:\stsmod\outputs\od-shared-gauge-20261109\reverse.log` (the sender's own OD again, the owner's ready vote again, a target that skips the side or the OD check or is the sender, a payload that drops the player).

The rest of the game side (the Harmony taps, the first-launch prompt, the dialog and the loaded-mod check) is compiled by the normal mod build and checked by `validation/beta-compat`; it is not exercised here.
