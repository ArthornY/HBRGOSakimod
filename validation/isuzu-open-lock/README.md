# 五十铃Open·the·lock验证

验证需求70：实际卡牌七项独立升级、费用、群体攻击命令、现有百分比减益、原生手牌选择和本回合费用清理，以及原生宝箱获配后的私有二选一。关联31E成员计数和31D预留原件，原投票／争夺流程不变。

商店、Boss奖励与普通RelicCmd.Obtain不安装拦截。只审计／替换宝箱UI普通状态机中的三个callsite：获取、动画与其他玩家袋的fallback各一个，参数、Task返回和原生命令保持一致。宝箱持牌者使用原生RelicSelectCmd及原生玩家选择同步；箱内所有获配项按原有顺序排队，客户端不会因本地／远程选择完成时间不同而改变抽袋／获得顺序。每玩家每箱最多一次额外件，原始物理获配回调幂等；未选件归袋，原生跳过选择时保留原件，异常退出归还两件并保留原生错误，等待时其它袋不能取到待选件。其他玩家袋的降级也等待同步选择和实际获得成功，仅所选件进入fallback，未选原件保留原队列层；失败不改其他玩家袋。

受控叶：AttackCommand.Execute仅记录原始伤害／段数，用户手牌／遗物选择与场景获得终端被记录。卡牌OnPlay、费用、升级、减益框架、真实遗物袋与额外候选服务不替换。没有运行Godot、真实多人、完整UI动画或打包。

使用阶段run-suite.ps1 -Suite isuzu-open-lock -Profile stable，完成后beta；同工程两profile顺序。报告含不可变候选DLL与原生profile。
