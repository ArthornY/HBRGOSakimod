93–94 native validation

This host binds to an explicit immutable production DLL and the pinned stable or beta game profile. `run-suite.ps1 -Suite 31x-yingxia-charlotta` builds only the validation executable. It does not build or distribute the mod.

It exercises native payment, `OnPlayWrapper`, automatic plays, replay generation, card-result piles, the real manual's shared upgrade ledger, all relevant production combat scopes and common arithmetic. The selector's user response, attack animation and terminal scene damage are controlled leaves; selection candidates, damage requests, hook dispatch, buff/debuff application, resource changes, actual hit receipts and inserted-turn coordination remain production behavior.

Covered behavior includes every formation, independent upgrade choices, two different simultaneous choices, rejected selections, source-based attribute snapshots, Artifact, party/phantom/pet targeting, the random four-hit skill attack, exact X payment and X=0, Flash, capped jealousy, own versus teammate cards, replays and separate ordinary/OD/personal turn ledgers. Actual command-hit OD is checked separately from the existing attack/skill card-use charge.

Regeneration heals the current team on the owner's next three actual turn starts. Engagement Ring pays after real energy reset and is consumed once; both native `SetupPlayerTurn` and the shared inserted-turn start are exercised. Vow and doll receipts are saved on the physical source card, shared by combat mirrors, reset for a new physical clone or fresh combat, and restored by native `SavedProperties` JSON. Delayed powers' inherited saved properties and Vow's standard independent-effect profile are also round-tripped through native save APIs.

Fixture upgrades use the real `HbrMemoryGardenProgression.Publish` operation. This is necessary when retaining the real Electronic Soldier Manual hooks: directly changing only a fixture card's upgrade list would correctly be overwritten by the manual's authoritative shared ledger on the next pile change. The host also installs the real physical-target capture patch before testing post-hit Fragile; it does not synthesize a target receipt.

No Godot engine, live selection screen, font renderer, live multiplayer transport, export, package, version or Git operation is performed. Those presentation/transport boundaries remain in-game acceptance work.
