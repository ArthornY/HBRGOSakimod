# Story direction runtime checks

This project covers the game-side reader for requirement101. The schema/asset and workshop suites are owned separately. All fixture narration is embedded under validation; none is placed in `story/`.

`PureChecks.csproj` links the actual production local animation clock. Its17 checks cover exact ticks, pause/cover, zero-duration endpoints, property-owner replacement, cancellation, fast-forward completion and exit cleanup. It uses no Godot/native engine.

`Checks.csproj` loads an explicitly hashed **real main DLL** against each original native profile. `Native.cs` executes actual `PrepareDirectionPage`, `ShowLine`, `ExecuteDirection`, `ApplySnapshot`, seek/cancel and tap gates, with only Godot mutation/view factories and audio terminals controlled. It also executes real renderer camera/filter interpolation with material/layout terminals controlled. White-out waits before an explicit scene; no-wait white-in overlaps later waits; continuation pages do not replay authored directions/voice; Ctrl discards transient actions but preserves persistent audio/scene state; back preserves angry-bubble type and stays silent; mini requires both tap and voice before its .5+.3 tail; black middle text waits for tap; long waits cancel; missing cut-ins do not block narration. Actual compiled local methods are audited for unintended synchronized-room/overlay calls. Additional focused checks preserve the old choice-background blur, keep old scene position changes immediate while fading character opacity, and ensure zero-duration cross-fade discards held images without flashing them. The last case controls only Godot Show/QueueFree calls at the actual method callsites, since direct no-engine Godot Node static initialization cannot run safely.

Run `outputs/story-directions-101-20261116/runtime/run-checks.ps1 -Profile stable|beta -Candidate <explicit real main DLL> -ReportName <name>.json`. It builds only this validation project, validates original native-profile hashes and runs without Godot. Use one profile at a time because both use the same project obj directory.

`SourceChecks.csproj` / `run-source-checks.ps1` are a **development-only fallback**, linking production direction/stage sources with a small reader UI-boundary fixture. Those reports explicitly set `sourceLinked:true, productionMainBinding:false`; they are not final main-DLL compatibility evidence. The fallback was used while root main-SDK builds were temporarily unavailable. `RenderCompile.csproj` independently checks actual renderer/schema sources against either native API with warnings as errors; it does not render them.

Runtime geometry is in1600脳900 design space. Original move coordinates convert by5/6 and flip Y; background camera offsets remain source-image pixels and clamp at crop bounds. Actor depth uses stable ascending Z with original scene order on ties (a2D layering convention, not a Unity depth renderer). Independent position/scale/blur/alpha and filter channels avoid one effect restarting unrelated unfinished animations. Local clock/RNG never touch combat RNG.

Frames/particles resolve through `data/story_effects.json`; a missing named effect is skipped and logged once, never replaced with an unrelated placeholder. `story_visuals.json` supplies actual framed cut-ins, original ADV bubbles/slices and mini images; missing numbered mini art is not invented. The original Novel font is applied only to newly directed dialogue bubbles and big/mini cut-in text, and preloaded only when those operations occur. Old reader body/name text, sound-effect lettering and middle black text retain their previous fonts. Optional `VoiceCharacter` binds an arbitrary actor ID to a verified cue character; known-cue ambiguity remains silent instead of guessing a display-name alias.

No real game/controller/mouse session, shader compilation, GPU output, sound playback/listening, face-patch pixel compositing or Unity-equivalent particle motion is claimed. The original effect families are reconstructed in2D from their own assets; resource/size/provenance receipts are separate. No `.face.json` author assets have been supplied in this task yet, so schema/bounds and renderer behavior cannot be reported as real face-image pixel verification.

The filter retains vertex tint while resampling textures, as required by the [Godot4.5 CanvasItem COLOR contract](https://docs.godotengine.org/en/4.5/tutorials/shaders/shader_reference/canvas_item_shader.html#color-and-texture). This preserves character fades; it is documentation review, not proof of rendered pixels.
