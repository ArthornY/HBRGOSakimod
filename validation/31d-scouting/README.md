# 31D scouting behavior host

Run sequentially with `outputs/31d-and-monsters-20261115/run-suite.ps1 -Suite 31d-scouting -Profile stable` and the beta profile with `-CheckArgs @('--isolate-telemetry')`. The runtime profile manifest and immutable candidate SHA are verified and recorded. Set `HBR_SCOUT_CASE_FILTER=treasure` only for an explicitly reported development-only treasure subset; the full run is the final evidence.

The main cases execute the actual scouting generator, saved-ledger queries, room/event entry helpers and native event/room data structures. Native `UnknownMapPointOdds.Roll` is compared directly with the preview routine across 30 seeds, tutorial and ordinary history, four blacklists and seven sequential unknown nodes: 1,680 comparisons check the chosen type, all evolving odds and consumed RNG counts. Further cases cover bottom-to-top/left-to-right queue order, preservation of every native RNG stream, native event queue and visited set, the real 30% memory gate and weighted repeat rules, shared deterministic ledgers, late fourth-member activation, retained current-act knowledge after a member is removed, new-act visibility, changed-node/live-condition fallback, all three no-consecutive-shop rules, actual native save reload, and future-ceremony eligibility without prematurely visiting the ceremony or meeting characters.

TreasureCases exercises real rarity rolls, shared/per-player bags, reservations, native synchronizer picking and award paths, eligibility/ownership changes, rollback, tutorial rewards, and release after walking past an unused chest's row. Beta-only native modes are asserted only when that runtime defines them; stable code does not invent those enum values.

Host boundaries: three ordinary events have controlled native `IsAllowed` predicates. The memory pool leaf supplies three real generated story types and preloads their unchanged authored JSON through System.IO, with the original probability/weight selector intact; their authored CustomID aliases are registered because this host omits BaseLib's startup initializer. The unrelated encounter encyclopedia cache is empty only while constructing native UnlockState; the tested odds, queues, event conditions and treasure logic are unchanged. HUD/map rendering, texture loading and visual waits are isolated. No Godot process, rendered map, live input, save file, package, Git or Steam operation is performed.
