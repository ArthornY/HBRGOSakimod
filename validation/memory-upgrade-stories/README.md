# Upgrade memory reader checks

`PureChecks.csproj` links the real new schema and original pure story validator. `Checks.csproj` loads an explicit built candidate against the original stable/beta native profile.

The runtime fixture executes the real catalog/cache and async presentation session, real NLibraryEvent local completion callbacks, and actual native ActiveScreenContext Harmony target. Resource reading/loading, Godot UI construction/visibility/destruction, and UI-ready/world validity are controlled leaves. The native focus return uses its actual production identity checks, with only the final native focus operation isolated. Native EventSynchronizer and InputSynchronizer methods are observed and may not be called. Cecil inspects the actual compiled attach/close/preview code for forbidden event/room/overlay/persistence calls.

No game engine or UI rendering is claimed. No fixture story is stored under `story/`, and the JSON template lives under the excluded docs tree. Upgrade queues, actor mapping, local records and configuration are covered by their separate owners.

The first complete reader binding uses main candidate `32A04B821745FB8ACC6369743B206459C734E5D289B79993629844A8EC7F2A87`: pure schema 44 checks and 56 reader checks on each original stable 0.107.1 / beta 0.113.1 profile. The completion case executes actual `NLibraryEvent.ShowChoices` in local mode, proving that the event-free branch returns before normal event option access. The normal event branch remains unchanged after that early return. See `outputs/memory-garden-upgrade-stories-100-20261116/reader/owned-reader-index-read_req28.json` for exact report and source bindings.

Run the pure project independently, or use `reader/run-checks.ps1 -Profile stable|beta -Candidate <explicit DLL>` in that stage for the native host. It only builds the validation project and never invokes Godot or changes delivered artifacts.
