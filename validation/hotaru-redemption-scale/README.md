# Redemption turn-amplification scale

`Run.ps1 -ModAssemblyPath <candidate.dll>` builds only this standalone validation host and checks the **same candidate DLL** against stable 0.107.1 and beta 0.113.1. Reports default to `outputs/hotaru-numeric-leaks-20261116/redemption/final/{stable,beta}/report.json`. `-ExpectOldBug` is an explicit old-candidate negative control: HBR actual 5000 must reproduce 5000%, rather than accepting the corrected 1% behavior.

The shared native stats fixture supplies native combat state and hook dispatch. This host calls the real cannon DamageCore, claims its real command scope, records controlled terminal HP/DP loss, binds and consumes the real one-use receipt, calls real `HotaruEndgameEffectsHelper.OnCannonDamage`, and lets native `PowerCmd.Apply` and production precision adapters retain the exact decimal percentage. HP+DP and multiple native result objects are checked for one combined award. The following damage uses the full native Hook/StrongestShield wrapper; next-turn clearing calls the real Millsage boundary and native Remove while preserving the separate ordinary amplification pool.

The native terminal HP/DP execution leaf is isolated to supply deterministic actual-loss cases, including blocked damage. Shared fixture logging/StringName and listener inventory are isolated. Beta telemetry isolation verifies that only the module initializer's Sentry call is removed in a report-local copy. Other FinishAfterDamageGiven reactions, full HP mutation, OD coordinator flow, rendering, and an actual in-game run are outside this test. It does not invoke Godot, export, package, or copy installed mod outputs.
